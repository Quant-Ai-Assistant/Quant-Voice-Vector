# Связь с Quant-Core

English version: [docs/en/quant-core.md](../en/quant-core.md)

У Quant Voice Vector и [Quant-Core](https://github.com/Quant-Ai-Assistant/Quant-Core) нет ничего
общего, кроме файла. Приложение ничего не знает о пользователях Quant-Core и не обращается к
его API.

| Проект | Что делает |
| --- | --- |
| Quant Voice Vector | Принимает звук, считает векторы, отдаёт `.qvoice.json` |
| Quant-Core | Принимает файл в профиль человека, определяет говорящего в каждой голосовой реплике |

Приём и хранение профилей на стороне Quant-Core ещё не написаны. Эта страница — спецификация
для них.

## Главное правило

Векторы от разных моделей или от одной модели с разной предобработкой несравнимы. Обе стороны
обязаны считать вектор в точности одинаково.

## Как вектор считает это приложение

1. **Декодирование** звука в отсчёты с плавающей точкой и сведение в моно усреднением каналов.
2. **Приведение** к 16 кГц через `LinearResampler` из sherpa-onnx.
3. **Удаление тишины** через Silero VAD: порог 0.5, минимальная тишина 0.5 с, минимальная речь
   0.25 с, окно 512 отсчётов, максимальная речь 20 с. Отрезки речи склеиваются.
4. **Нарезка** речи на отрезки по 8 секунд. Последний отрезок короче 3 секунд отбрасывается.
5. **Расчёт** вектора для каждого отрезка: создать поток, `acceptWaveform(16000, samples)`,
   затем `inputFinished()`, затем `compute`.
6. **Нормализация** вектора к единичной длине (L2). Сырой выход модели не нормализован.

Закреплённые значения находятся в
[`crates/qvv-core/src/model.rs`](../../crates/qvv-core/src/model.rs) и
[`engine.rs`](../../crates/qvv-core/src/engine.rs):

| Что | Значение |
| --- | --- |
| Движок | sherpa-onnx 1.13.8 |
| Модель | `3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx` |
| SHA-256 модели | `aa3cfc16963a10586a9393f5035d6d6b57e98d358b347f80c2a30bf4f00ceba2` |
| Длина вектора | 192 |
| VAD | `silero_vad.onnx`, SHA-256 `9e2449e1087496d8d4caba907f23e0bd3f78d91fa552479bb9c23ac09cbb1fd6` |

## Что должен сделать Quant-Core

- Использовать `sherpa-onnx-node` той же версии с тем же файлом модели и проверять его SHA-256
  при запуске.
- Отклонять профиль, у которого `model.id` или `model.sha256` отличается от собственных.
- Для входящей голосовой реплики (по умолчанию Opus в WebM) повторять шаги 1–3 и 5–6 на всей
  реплике, затем сравнивать вектор с профилями.
- **Вызывать `inputFinished()` перед `compute`.** Без него последние кадры не обрабатываются, и
  тот же звук даёт немного другой вектор: косинус около 0.999 вместо 1.
- Подбирать порог узнавания на своих данных. Это приложение только показывает близость.

## Что измерено

- **Rust и Node.js сходятся.** На 20 тестовых записях векторы из крейта для Rust и из
  `sherpa-onnx-node` совпали до шестого знака при одинаковом порядке вызовов.
- **Opus не мешает.** Одна и та же запись до и после сжатия Opus на 24 кбит/с давала близость
  0.93–0.99 сама с собой.
- **Разные микрофоны важнее кодека.** Один человек через два микрофона давал примерно 0.5–0.8;
  другой человек в нашем небольшом наборе оставался ниже примерно 0.5.

Набор был небольшим: пять говорящих на китайском и английском и по одному мужскому и женскому
голосу на русском. Мужской голос против другого мужского на русском не проверялся.

## Когда меняется модель

Все существующие профили становятся бесполезными, и их нужно записать заново. Константы в
`model.rs`, модель в Quant-Core и эту страницу меняйте в одном релизе.
